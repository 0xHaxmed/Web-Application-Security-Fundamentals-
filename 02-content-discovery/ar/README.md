## 🎯 النظرة العامة والنموذج الذهني (Mental Model)

"استكشاف المحتوى" (Content Discovery) هو عملية البحث المنظم عن الملفات، والمجلدات، والنطاقات الفرعية، والمضيفين الافتراضيين (Virtual Hosts) **غير المرتبطين بروابط صريحة** في واجهة المستخدم للموقع.

في سيناريوهات اختبار الاختراق الحقيقية، نادراً ما تترك الشركات ثغرات حرجة في واجهتها الرئيسية. الثغرات القاتلة تتواجد بنسبة تتجاوز 90% في: **بيئات التطوير المنسية (Staging/Dev)، النسخ الاحتياطية المتروكة، لوحات الإدارة غير المعلنة، والملفات المؤقتة**.

### معمارية الاستطلاع ثلاثية الطبقات (Tri-Layer Recon)
المختبر المحترف لا يقتصر على أداة واحدة، بل يدمج ثلاث طبقات متكاملة:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. الاستكشاف اليدوي (Manual Discovery)                       │
│ فائق السرعة، معدوم الضجيج، دقيق للغاية.                     │
│ • robots.txt (حدود وتوجيهات الزواحف)                        │
│ • sitemap.xml (خرائط الروابط وصفحات الاختبار)               │
│ • ترويسات HTTP (بصمات الخوادم، X-Powered-By، الهيدرز المخصصة)│
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 2. استخبارات المصادر المفتوحة (OSINT)                        │
│ فحص سلبي تماماً لا يمكن للهدف كشفه أو رصده.                 │
│ • Google Dorking (معاملات البحث المتقدمة site:, inurl:)     │
│ • Wayback Machine (أرشيف الإنترنت والصفحات التاريخية المحذوفة)│
│ • GitHub (أسرار المطورين المحفوظة في تاريخ الـ Commits)     │
│ • الحوسبة السحابية (تخمين أسماء حاويات AWS S3 العامة)       │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 3. التخمين الآلي عبر القواميس (Gobuster)                     │
│ تغطية شاسعة لا يمكن للإنسان مجاراتها يدوياً.                │
│ • تخمين المجلدات والملفات (`dir`)                           │
│ • تخمين النطاقات الفرعية الحقيقية عبر الـ DNS (`dns`)       │
│ • تخمين المضيفين الافتراضيين الداخليين بالسيرفر (`vhost`)    │
└─────────────────────────────────────────────────────────────┘
```

## 📋 تفكيك التاسكات ومنهجية الاستدلال (Task Breakdown)

### Task 1 — Introduction (التأكد من تشغيل المعمل)
* **المفهوم:** تشغيل الآلة والتأكد من استجابتها لطلبات الـ HTTP قبل إطلاق أدوات الفحص:
  ```bash
  curl -sI http://MACHINE_IP/
  ```

---

### Task 2 — Manual Discovery: Common Files (الملفات الشائعة)

#### 1. ملف `robots.txt`
* **المفهوم الأمني الحرج:** ملف `robots.txt` هو مجرد **وثيقة استرشادية** لمحركات البحث الملتزمة (مثل Googlebot) لتخبرها بما يُفضل ألا يُفهرس. **هو ليس أداة حماية أو تحكم في الوصول (Not an Access Control)**.
* عندما يضع المطور مساراً تحت سطر `Disallow:`، فهو يقدم لمختبر الاختراق خريطة كنز مجانية: *"هذا المجلد حساس ولا أريد للعامة أن تجده عبر جوجل!"*.
* **منهجية الحل:**
  1. اطلب الملف مباشرة عبر المتصفح أو الطرفية:
     ```bash
     curl -s http://MACHINE_IP/robots.txt
     ```
  2. ابحث عن الأسطر التي تبدأ بـ `Disallow:`.
  3. خذ المسار المكتوب وتوجه إليه مباشرة في المتصفح.

#### 2. ملف `sitemap.xml`
* **المفهوم الأمني:** ملف XML يُنشأ لإرشاد محركات البحث لهيكل الموقع. غالباً ما يُنشأ تلقائياً بواسطة أنظمة إدارة المحتوى (CMS)، مما يؤدي لضم صفحات تجريبية، أو مسارات سرية، أو صفحات صيانة نسِي المطور إزالتها.
* **منهجية الحل:**
  1. اطلب الرابط `http://MACHINE_IP/sitemap.xml`.
  2. استعرض وسوم `<loc>`.
  3. ابحث عن الروابط الشاذة أو الغريبة (مثل مسارات مكتوبة بأسلوب أرقام بديلة للحروف `leetspeak` أو أسماء صفحات إدارية وسرية).

---

### Task 3 — Manual Discovery: Framework Stack & Headers

#### 1. فحص ترويسات الاستجابة (HTTP Headers)
* **المفهوم:** يرسل الخادم معلومات تقنية في الهيدرز. أحياناً يضيف المطور هيدرز مخصصة (Custom Headers) لغايات التصحيح واختبار التطبيق (Debugging) وينسى إزالتها في الإنتاج.
* **منهجية الحل:**
  1. أرسل طلب فحص للهيدرز:
     ```bash
     curl -v http://MACHINE_IP/
     # أو
     curl -I http://MACHINE_IP/
     ```
  2. دقق في كافة الأسطر الراجعة؛ ابحث عن أي هيدر غير تقليدي يبدأ بـ `X-` (مثل `X-FLAG` أو ما شابه).

#### 2. توثيق إطار العمل وبيانات الدخول الافتراضية
* **المفهوم:** بمجرد تحديد اسم إطار العمل (Framework) من التعليقات أو الهيدرز، يجب التوجه فوراً لصفحة التوثيق الرسمية (Documentation).
* **منهجية الحل:**
  1. حدد اسم الإطار وإصداره من أسفل كود الصفحة.
  2. ابحث في توثيقه الرسمي عن: ما هو المسار الافتراضي للوحة التحكم الإدارية؟ (مثل `/admin` أو `/thm-framework-login`).
  3. ابحث عن بيانات الاعتماد الافتراضية للمسؤول (مثل `admin:admin` أو `admin:password`).
  4. توجه للمسار واكتب البيانات الافتراضية؛ عند نجاح الدخول ستعرض لوحة الإدارة الفلاج المطلوب.

### Task 4 — OSINT: Search Engines & Web Tools

#### 1. معاملات جوجل المتقدمة (Google Dorking)
* **المفهوم:** استغلال محرك بحث جوجل للوصول إلى صفحات وملفات مفهرسة لم يكن صاحب الموقع يقصد إتاحتها للعلن.
* **أهم المعاملات الأمنية:**
  | المعامل | الوظيفة | مثال عملي |
  |---|---|---|
  | `site:` | حصر البحث داخل نطاق محدد حصراً | `site:example.com` |
  | `inurl:` | البحث عن كلمة محددة داخل رابط الصفحة (URL) | `site:example.com inurl:admin` |
  | `filetype:` | حصر البحث بنوع ملف أو امتداد معين | `site:example.com filetype:pdf` أو `filetype:sql` |
  | `intitle:` | البحث عن كلمة في عنوان الصفحة المعروض بالمتصفح | `site:example.com intitle:"login"` |
  | `intext:` | البحث عن نصوص محددة في جسم الصفحة | `site:example.com intext:"confidential"` |
  | `cache:` | عرض النسخة المخزنة مؤقتاً لدى جوجل للصفحة | `cache:example.com` |

#### 2. إضافة Wappalyzer
* **المفهوم:** أداة فحص سلبية (إضافة متصفح / مكتبة برمجية) تقوم بفحص أكواد الجافاسكريبت، وهيدرز الـ HTTP، وملفات الكوكيز لترسم بصمة شاملة بالتقنيات المستخدمة (أنظمة CMS، خوادم الويب، لغات البرمجة، شبكات CDN) مع أرقام إصداراتها بدقة.

### Task 5 — OSINT: Archives & Repositories

#### 1. أرشيف الإنترنت (Wayback Machine)
* **الرابط:** `https://archive.org/web/`
* **القيمة لمختبر الاختراق:** تحتفظ الأداة بلقطات تاريخية لصفحات الويب منذ عام 1996. يفيد ذلك في العثور على صفحات تسجيل دخول قديمة، أو وثائق ملغاة، أو مسارات API نسيتها الشركة؛ فرغم حذف الرابط من واجهة الموقع الحالية، غالباً ما يظل مسار الـ Backend القديم يعمل على الخادم!

#### 2. مستودعات الأكواد (GitHub Repositories)
* **المفهوم:** يرفع المطورون أحياناً مشاريعهم على مستودعات عامة بالخطأ، متضمنة ملفات `.env` ومفاتيح سرية.
* **القاعدة الذهبية الأهم:**
  > **حذف السر أو ملف الـ .env في Commit لاحق لا يحذفه من المستودع!**
  > طالما أن الـ Commit History لم يُعد كتابته وتطهيره بأدوات مثل `git-filter-repo`، فإن السر يظل موجوداً للأبد في سجلات الـ Git السابقة ويستطيع أي شخص استخراجه بفحص الفروقات (`diffs`).

#### 3. حاويات التخزين السحابي (AWS S3 Buckets)
* **النمط القياسي للرابط:** `https://{اسم-الحاوية}.s3.amazonaws.com`
* **المفهوم:** إذا تم ضبط صلاحيات الحاوية على خيار "Publicly Accessible"، يمكن لأي شخص تحميل الملفات المخزنة بداخلها دون أي تحقق.
* **أنماط التخمين الشهيرة:**
  * `{company}-assets`
  * `{company}-backup`
  * `{company}-dev` / `{company}-staging`

### Task 6 — Automated Discovery: Gobuster Fundamentals

أداة Gobuster أداة سريعة جداً مكتوبة بلغة Go لتخمين المسارات والملفات عبر قواميس الكلمات (Wordlists).

```
       [ قاموس الكلمات (SecLists) ]
       ├── admin
       ├── backup        طلب GET إلى: http://TARGET/FUZZ
       ├── api       ────────────────────────────────────▶ [ خادم الويب ]
       └── secret                                                 │
                                                                  ▼
                      [ أكواد الاستجابة HTTP ] ◀──────────────────┘
                       • 200 OK (المسار موجود!)
                       • 301/302 (إعادة توجيه)
                       • 403 Forbidden (المجلد موجود لكن ممنوع التصفح)
```

#### الرايات الأساسية (Flags):
* `-u`: رابط الهدف المراد فحصه.
* `-w`: مسار ملف القاموس (عادة من حزمة SecLists).
* `-x`: امتدادات الملفات المراد البحث عنها (مثل `-x php,txt,html,log`).
* `-t`: عدد خيوط المعالجة المتزامنة Threads (الافتراضي 10).
* `-o`: مسار حفظ النتائج في ملف خارجي.
* `--delay`: مهلة زمنية بين الطلبات لتجنب الحظر أو إرهاق السيرفر.

#### التنفيذ العملي:
```bash
gobuster dir -u http://MACHINE_IP/ \
  -w /usr/share/wordlists/SecLists/Discovery/Web-Content/common.txt \
  -t 20 -x txt,php,html,log
```
* **الاستدلال:**
  * ابحث في النتائج عن المجلد المكتشف الذي يبدأ اسمه بـ `mo/`.
  * ابحث عن أي ملف ينتهي بامتداد السجلات `.log`.

### Task 7 — Automated Discovery: Subdomains vs. Virtual Hosts

هذا هو الفارق المفاهيمي والعملي الأهم في هذا الروم بالكامل:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. النطاق الفرعي (Subdomain - يُحل عبر الـ DNS)                             │
│ الطلب: blog.example.com                                                     │
│                                                                             │
│ [ المتصفح ] ──▶ [ سيرفر الـ DNS ] ──▶ يرجع عنوان الـ IP: 10.10.20.5         │
│ [ المتصفح ] ────────────────────────▶ يتصل بالسيرفر 10.10.20.5              │
│                                                                             │
│ • وضع الأداة: `gobuster dns -d example.com -w wordlist.txt`                 │
│ • متى يفشل؟ إذا لم يكن للنطاق الفرعي سجل A record مسجل لدى سيرفر الـ DNS.  │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. المضيف الافتراضي (Virtual Host - يُحل داخلياً بواسطة خادم الويب)          │
│ يُرسل الطلب مباشرة إلى IP الخادم الثابت مع تغيير هيدر:                      │
│ Host: internal-dev.example.com                                              │
│                                                                             │
│ [ المتصفح ] ──▶ يرسل طلب HTTP لنفس الـ IP مع هيدر `Host: internal-dev` ──┐  │
│                                                                           ▼ │
│ [ خادم الويب Apache / Nginx ] ◀───────────────────────────────────────────┘ │
│ يقرأ السيرفر قيمة الهيدر Host ويوجه الطلب داخلياً للمجلد المخصص له!         │
│                                                                             │
│ • وضع الأداة: `gobuster vhost -u http://IP --domain example.thm -w list`    │
│ • ينجح حتى لو لم يكن هناك أي سجل DNS مسجل لهذا النطاق الافتراضي إطلاقاً!   │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### تجهيز بيئة الفحص (حل النطاقات محلياً):
قبل تشغيل الفحص في المعمل، يجب إخبار الآلة بمكان خادم الـ DNS:
```bash
echo "MACHINE_IP nameserver" >> /etc/resolv-dnsmasq
systemctl restart dnsmasq
# أو إضافة النطاق مباشرة لملف الهوستس:
echo "MACHINE_IP acmeitsupport.thm" >> /etc/hosts
```

#### فحص النطاقات الفرعية (DNS Mode):
```bash
gobuster dns -d acmeitsupport.thm \
  -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt \
  --wildcard
```
* `--wildcard`: تجبر الأداة على المتابعة وتجاوز استجابات الـ Wildcard التي قد تعطي نتائج إيجابية كاذبة لكل الكلمات.

#### فحص المضيفين الافتراضيين (vhost Mode):
```bash
gobuster vhost -u http://MACHINE_IP/ \
  --domain acmeitsupport.thm \
  -w /usr/share/wordlists/SecLists/Discovery/DNS/subdomains-top1million-5000.txt \
  --append-domain \
  --exclude-length 250-320
```
* `--append-domain`: تلحق النطاق الأساسي بكل كلمة من القاموس تلقائياً.
* `--exclude-length`: تستبعد النتائج التي تتطابق في حجم الاستجابة مع صفحة الخطأ الافتراضية لتصفية النتائج الزائفة (False Positives).
* **الاستدلال:** قم بعدّ الأسطر أو المضيفين الافتراضيين الذين يرجعون كود حالة `200 OK`.

### Task 8 — خاتمة الروم
* عملية الاستكشاف هي حلقة تراكمية تبدأ باليدوي، ثم بالبحث السلبي الخارجي (OSINT)، ثم بالتخمين الآلي الموسع.
* الفهم الدقيق لآلية عمل البروتوكولات (مثل كيفية قراءة السيرفر لهيدر `Host:` في الـ vhosts) هو الفارق الجوهري بين مختبر الاختراق المحترف والشخص الذي يشغل أدوات دون وعي بآليتها.
