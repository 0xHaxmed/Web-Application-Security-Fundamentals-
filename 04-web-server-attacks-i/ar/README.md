## 🎯 النظرة العامة والنموذج الذهني (Mental Model)

ينقلنا هذا الروم من ثغرات منطق التطبيقات البرمجية إلى مستوى البنية التحتية: **خوادم الويب المضيفة على نظام لينكس**. يركز الروم تحديداً على **استكشاف وتوثيق أخطاء الإعداد الشائعة (Misconfigurations)** دون الدخول في الاستغلال العنيف، عبر مقارنة 4 خوادم ويب أساسية: **Apache2، خادم بايثون المدمج، Node.js (Express)، و Nginx**.

### القاعدة الذهبية لمختبر الاختراق:
> **"الإعدادات الافتراضية في كل خوادم الويب تفضل دائماً سهولة النشر وتسهيل تشخيص الأخطاء للمطور على حساب الأمان."**

عندما يجد المختبر لوحة إحصائيات مكشوفة، أو رسائل أخطاء تفصيلية، أو فهرسة مفتوحة للمجلدات، فغالباً ما يكون السبب هو **أن الإعدادات الافتراضية لم تُراجع نهائياً قبل النشر في بيئة الإنتاج**.

```
                           [ طبقة خوادم الويب ]
        ┌───────────────────┬───────────────────┬───────────────────┐
        ▼                   ▼                   ▼                   ▼
    [ Apache2 ]         [ Python ]          [ Node.js ]          [ Nginx ]
    (منفذ 80)           (منفذ 8000)         (منفذ 3000)         (منفذ 8080)
   • mod_status        • انعدام التحكم     • تسريبات وضع       • stub_status
     (/server-status)    في الوصول           التطوير dev         (/nginx_status)
   • Options +Indexes  • كشف ملفات         • مسارات الفحص      • autoindex on;
   • تسريب ملفات         النقطة (.env)       (/api/routes)     • server_tokens
     النسخ .bak          • الأرشيفات         • تسريب متغيرات     وكشف الإصدار
   • كشف .htpasswd       المضغوطة            البيئة env
```

## 📋 تفكيك التاسكات ومنهجية الاستدلال (Task Breakdown)

### Task 1 — Introduction (الخدمات والمنافذ)
* **المنافذ والخوادم في المعمل:**
  * **المنفذ 80:** خادم Apache2.
  * **المنفذ 8000:** خادم Python HTTP Server المدمج.
  * **المنفذ 3000:** خادم Node.js / Express.
  * **المنفذ 8080:** خادم Nginx.

---

### Task 2 — Identifying Web Servers (تحديد هوية الخوادم)

#### 1. استخراج البصمة عبر ترويسات الاستجابة (Headers)
كل خادم يملك سلوكاً وهيدرز افتراضية تكشف هويته:
```bash
# سكريبت لفحص الترويسات عبر المنافذ الأربعة
for port in 80 8000 3000 8080; do
  echo "=== PORT $port ==="
  curl -sI http://MACHINE_IP:$port/ | grep -iE "server|x-powered-by"
done
```

| المنفذ | نوع الخادم | الهيدر الأساسي لكشف الهوية | القيمة الافتراضية |
|---|---|---|---|
| **80** | Apache2 | `Server:` | `Apache/2.4.x (Ubuntu)` |
| **8000** | Python HTTP Server | `Server:` | `SimpleHTTP/0.6 Python/3.xx.x` |
| **3000** | Node.js Express | `X-Powered-By:` | `Express` *(يحذف هيدر Server افتراضياً)* |
| **8080** | Nginx | `Server:` | `nginx/1.xx.x` |

#### 2. البصمة الثانوية: صفحات الخطأ الافتراضية (404 Error Pages)
حتى إذا قام المدير بحذف ترويسة `Server`، فإن شكل صفحة الخطأ 404 يكشف هوية الخادم:
* **خادم بايثون:** صفحة نصية بسيطة جداً: `Error code: 404. Message: File not found.`
* **خادم إنجنكس:** صفحة HTML بمنتصفها تذييل يحتوي على رقم الإصدار: `<center>nginx/1.xx.x</center>`.
* **خادم أباتشي:** صفحة HTML منظمة تحتوي اسم المضيف ورقم المنفذ ونظام التشغيل.

---

### Task 3 — Python's Built-In HTTP Server (انعدام التحكم بالوصول)

#### 1. المفهوم والخطورة الواقعية
خادم بايثون المدمج (`python3 -m http.server 8000`) أداة سريعة طورها مهندسو بايثون لمشاركة الملفات محلياً، وليست مخصصة للإنتاج نهائياً.
* **الخلل القاتل:** لا يحتوي على أي نظام للمصادقة، ولا يملك أي آلية لحظر ملفات النقطة (Dotfiles).
* على عكس أباتشي وإنجنكس اللذين يمنعان تحميل الملفات التي تبدأ بنقطة، يقوم خادم بايثون بتقديم أي ملف موجود في مسار تشغيله للعامة!

#### 2. استخراج الملفات المتروكة:
1. **تحميل ملفات البيئة (`.env`):**
   ```bash
   curl -s http://MACHINE_IP:8000/.env
   ```
   * *الاستدلال:* ابحث عن بيانات الاتصال بقاعدة البيانات: `DATABASE_URL=mysql://...` واستخرج كلمة المرور الموجودة بين اسم المستخدم والمضيف.
2. **تحميل الأرشيفات المضغوطة (`backup.zip`):**
   * عند وجود فهرسة للمجلدات، يتم تحميل الأرشيف وفك ضغطه:
     ```bash
     curl -s http://MACHINE_IP:8000/backup.zip -o backup.zip
     unzip backup.zip -d backup-contents/
     ```
   * *الاستدلال:* استعرض الملفات المستخرجة للبحث عن الفلاج أو نصوص الملاحظات وقواعد البيانات.

---

### Task 4 — Apache2: الفهرسة، `mod_status`، والملفات المنسية

#### 1. كشف تفاصيل النظام (`ServerTokens`)
* القيمة الافتراضية في توزيعة أوبونتو هي `ServerTokens OS`، مما يكشف رقم إصدار أباتشي الدقيق مع اسم نظام التشغيل التابع له (`Apache/2.4.x (Ubuntu)`).

#### 2. فهرسة المجلدات (`Options +Indexes`)
* إذا دخلت لمجلد لا يحتوي ملف `index.html`، يقوم أباتشي بعرض شجرة الملفات بالكامل.
* فحص المجلد الشائع: `http://MACHINE_IP/files/`.

#### 3. كشف لوحة الإحصائيات الحية (`mod_status` / `/server-status`)
* **ماذا تكشف؟** عناوين IP للزوار المتصلين حالياً، الروابط المطلوبة، العمليات النشطة (Workers)، واستهلاك المعالج.
* **خطأ الإعداد:** من المفترض أن تكون محصورة لـ `localhost` عبر توجيه `Require local`. لكن وجود سطر `Require all granted` في أي ملف إعداد لمضيف افتراضي داخل الخادم يقوم **بإلغاء هذا القيد سراً وتعميمه على الخادم بالكامل!**
* **أمر الفحص:**
  ```bash
  curl -s http://MACHINE_IP:80/server-status
  ```

#### 4. استكشاف ملفات النسخ الاحتياطية و `.htpasswd`
* ينشئ المطورون ملفات مثل `config.php.bak` أو ينسون ملف كلمات مرور المصادقة الأساسية `.htpasswd`.
* **أمر Gobuster:**
  ```bash
  gobuster dir -u http://MACHINE_IP:80/ \
    -w /usr/share/wordlists/SecLists/Discovery/Web-Content/common.txt \
    -x bak,txt,old -t 20
  ```
* **الأهمية القصوى لملف `.htpasswd`:** يحتوي على تجزئات (Hashes) لكلمات مرور مستخدمي الموقع (غالباً بتشفير bcrypt أو MD5)، ويمكن كسرها دون اتصال (Offline Cracking) بأدوات مثل John the Ripper.

### Task 5 — Node.js (Express): تسريبات وضع التطوير (Development Mode)

#### 1. وضع التطوير مقابل الإنتاج (`NODE_ENV`)
في تطبيقات Express، ضبط المتغير `NODE_ENV=production` يعطل رسائل التصحيح ويحسن الأداء. ترك القيمة `development` في الإنتاج يسبب كوارث أمنية.

#### 2. أبرز تسريبات وضع التطوير في Express:
1. **تتبعات الأخطاء المفصلة (Verbose Stack Traces):** كتابة معالج أخطاء مخصص (Custom Error Handler) يطبع كامل مسارات السيرفر ومكتبات الـ npm عند حدوث خطأ 500.
2. **مسارات حصر الروابط (`/api/routes`):** يقوم بعض المطورين بإنشاء مسار يقرأ مصفوفة التوجيه الداخلية للإطار (`app._router.stack`) لطرد كل روابط الـ API المسجلة؛ مما يوفر على المختبر عناء التخمين!
3. **طباعة متغيرات البيئة (`process.env`):** توفير مسار مثل `/api/debug/env` يعيد كائن `process.env` بصيغة JSON، كاشفاً مفاتيح API ومؤكداً أن `NODE_ENV` مضبوط على `development`.
4. **الأسرار في ملفات الـ JS الثابتة:** تحتوي ملفات الواجهة الأمامية (`/static/app.js`) على روابط واجهات API داخلية ومفاتيح تجريبية.

#### 3. ملاحظة حول ملفات النقطة في Express:
* على عكس خادم بايثون، تقوم دالة `express.static()` بإرجاع كود `404 Not Found` تلقائياً لأي ملف يبدأ بنقطة (مثل `.env`) حمايةً للتطبيق.

### Task 6 — Nginx: خاصية `autoindex` ولوحة `stub_status`

#### 1. كشف الإصدار (`server_tokens`)
* التوجيه `server_tokens on;` هو الافتراضي؛ ويكشف رقم إصدار إنجنكس في الهيدرز وفي أسفل صفحات الخطأ.
* الترقيع يتطلب كتابة: `server_tokens off;`.

#### 2. فهرسة المجلدات (`autoindex on;`)
* على عكس أباتشي، يعطل إنجنكس الفهرسة افتراضياً.
* لا تظهر الفهرسة إلا إذا قام المدير بتفعيلها صراحة داخل كود التوجيه:
  ```nginx
  location /files/ {
      autoindex on;
      root /var/www/nginx/;
  }
  ```

#### 3. موديول قياس الاتصالات الحية (`stub_status` / `/nginx_status`)
* يوفر إنجنكس موديول `stub_status` لمراقبة الاتصالات:
  ```
  Active connections: 1 
  server accepts handled requests
   15 15 15 
  Reading: 0 Writing: 1 Waiting: 0 
  ```
* **الإعداد الآمن:** تقييده بـ `allow 127.0.0.1; deny all;`.
* **خطأ الإعداد الشائع:** استبداله بـ `allow all;` مما يتيح لأي شخص بالإنترنت مراقبة حركة اتصالات السيرفر.

### Task 7 — غياب ترويسات الأمان المشتركة وفحص Nikto

#### 1. فحص الترويسات المفقودة (Missing Security Headers)
افتراضياً، **لا يقدم أي من الخوادم الأربعة أياً من ترويسات الأمان الحديثة** إلا إذا قام المهندس بضبطها يدوياً.

```bash
# سكريبت فحص ترويسات الأمان
for port in 80 8000 3000 8080; do
  echo "=== فحص المنفذ $port ==="
  curl -sI http://MACHINE_IP:$port/ | grep -iE "x-frame-options|x-content-type-options|content-security-policy|strict-transport-security|referrer-policy" || echo "[-] لا توجد أي ترويسة أمان!"
done
```

#### 2. جدول ترويسات الأمان الإلزامية:
| الترويسة | القيمة الموصى بها | الهجوم الذي تمنعه |
|---|---|---|
| `X-Frame-Options` | `DENY` أو `SAMEORIGIN` | هجمات اختطاف النقر (Clickjacking) عبر إطارات `<iframe>` |
| `X-Content-Type-Options` | `nosniff` | هجمات تخمين نوع المحتوى (MIME Sniffing) |
| `Content-Security-Policy` | `default-src 'self';` | حقن الأكواد الخبيثة و Cross-Site Scripting (XSS) |
| `Strict-Transport-Security` | `max-age=31536000` | إجبار المتصفح على الاتصال المشفر HTTPS ومنع التنصت |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | منع تسريب التوكنات والروابط الحساسة في هيدر Referer |

#### 3. الفحص التلقائي بأداة Nikto:
```bash
nikto -h http://MACHINE_IP:80 -nointeractive
```
* تكتشف أداة Nikto بسرعة غياب الهيدرز الأمنية وتسجل تنبيهات أمنية حول المجلدات المفهرسة (`/files/`).

### Task 8 — خاتمة الروم ومصفوفة المقارنة النهائية

|---|---|---|---|---|
| **كشف الإصدار** | `ServerTokens OS` | مدمج في هيدر Server | هيدر `X-Powered-By` | `server_tokens on;` |
| **فهرسة المجلدات** | `Options +Indexes` | مفتوحة تلقائياً لكل المسار | غير مفعلة افتراضياً | `autoindex on;` |

| **ملفات النقطة (.env)**| محظورة افتراضياً | **مكشوفة بالكامل!** | محظورة في `express.static` | تعتمد على الإعداد |
| **ترويسات الأمان** | غائبة افتراضياً | غائبة افتراضياً | غائبة افتراضياً | غائبة افتراضياً |
